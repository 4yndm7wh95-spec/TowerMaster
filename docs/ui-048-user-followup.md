# 0.0.48 用户补充：完整动画与真正的原版卡牌

## 动画要求纠正（优先）

用户原话：『塔主的动作不应该只有几帧 我要的是完整的动画』『如果你还不太确认可以再找claude要清楚』。

当前 master-animation-plan.md 选择了“不做逐帧角色动画”、3 张关键姿势加补间；这与用户要求不一致。请 Claude 重新设计从起手、施法/埋牌到收势回归待机的完整角色动画，不要把姿势换图加小幅位移当作完整动画交付。动作幅度仍须小，风格有质感；完整指连贯的动作过程，不等于大幅挥舞。

由 Claude 决定实现技术和制作路径，先明确可行性、动作阶段、帧数/时长、循环/回归、角色一致性、透明图层、落点以及详细自足的制作 prompt。如果生图不足以稳定完成，应提出更适合的动画制作方式，不要继续盲目批量生成关键姿势。通用埋牌不泄露具体陷阱；易伤、格挡等效果仍需独立表现。

已经按旧方案生成的 5 个资源只作为未接入的视觉样例，不代表完整动画验收通过。美术继续制作暂停，等待 Claude 修订方案。

## 卡牌应直接照原版结构与表现

用户原话：『卡牌的具体说明这里看得出来还没有照搬原版的卡牌结构，原版是右键这个卡牌然后会有介绍 让claude按原版的结构来』『还有卡牌介绍这些文字理应简洁』。

进一步澄清原话：『不是说沿用原版的逻辑，而是这些卡牌就应该照抄原版』。

请将塔主/陷阱卡真正接入原版卡牌框架，直接使用原版的卡牌展示、放大、右键详情和关键词介绍等结构与表现，只换成塔主牌内容。不能用自绘悬停说明面板代替原版详情，也不能另写一个模仿原版的操作流程当作满足要求。请核对选择界面是否在外层 Button 包装时拦截了原版右键查看入口。

文案简洁：卡面以触发条件与主要效果为主；详细约束进入原版详情/规则说明，避免卡面和外置框同时大段重复。具体改稿与结构由 Claude 判断，参考用户截图 screenshots/ui048-user-card-details.png。
## 信息表达尽量图形化

用户原话：『还有少用文字来表达信息，比如塔主手里有几张牌这种，完全可以用UI来表示 比如在塔主旁边用卡牌 再标个数字 我这里只是举例 具体让claude评估和修改』。

这是整体 UI 方向，不是指定只能采用例子。请 Claude 评估信息条、塔主形象附近、召唤、陷阱状态、提示与战报，优先用图形/图标/数字直观表达张数和状态，减少说明句；必要规则进入原版详情或辅助说明。应保留可读性和保密性，不用难辨认的图标替代必须解释的规则，也不要把更多小组件挤到怪物、意图或手牌上。

只读定位：当前选陷阱卡面通过 `VanillaCard.cs:38` 的 Create 创建，`:48`设置 card.MouseFilter=Ignore，`:95` 起 Populate 用模板 Model 后覆盖文字，而非把实际陷阱 CardModel 绑定到这个卡面。`TrapDraftPanel.cs:192` 给外层 Button 绑定自绘 Ui.Tip。它确实主要是在套原版场景外观；请 Claude 改为真实塔主/陷阱模型及原版查看入口，避免原版详情打开后反而显示模板卡。这里没有改代码。
## 问号房产生战斗也需要塔主召唤

用户原话：『问号房有时候是会出怪，但是也还是要塔主布置怪物才对 这个问题咋解决呢 问问claude也』。

本轮实机：第一局 Overgrowth 的 (1,13) 问号房，实际进入 VineShambler 战斗，但没有召唤面板，直接按原版出怪。随后助手误以为还是非战斗房，提前投票下一格，造成动作队列停住；这两件事应分别记录，不能把操作时序错误当成问号房必须跳过召唤的理由。

请 Claude 设计并修复：问号结果已经确定为战斗后、战斗正式创建前暂停进入召唤阶段；两端一致采用确认后的清单，不能先开原版战斗再硬替换。请分别评估普通随机问号战斗、事件强制/特殊战斗、专用场景，以及标准开销、开局保护场数、奖励、读档/重连等规则。必要时补测试接口状态和等待条件，避免助手在问号战斗创建期间提前投票。具体挂点和方案由 Claude 决定。
