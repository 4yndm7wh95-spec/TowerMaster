## 尚存失败：完整重启未按账本重发牌组

稳定观测一次，复现步骤：

1. 第一局 (6,9) 休息处删易伤。真实塔主牌组 12 张，不含 act:vulnerable@1；账本余额 15，已打 3 场。
2. 同进程读档确认依然 12 张、不含易伤。此时才正常回主菜单，Quit 两个测试实例。
3. 用原 A/B 脚本重新启动，再通过原版多人读档大厅恢复同一局。
4. 房间稳定后钱包恢复 15/3 场、选牌界面未重复出现，但真实塔主牌组变成 13 张，易伤重新出现。过了一段时间再次读取仍未纠正。
5. 本地账本文件仍有 `RemovedCards: ["vulnerable"]`，所以不是删除记录没写盘。

```text
[01:41:05.996] INFO 塔主账本：读档，召唤点 15，已打 3 场
```

该次恢复之后没有“读档后按账本同步牌组”行；与同进程读档形成明确对照。截图：[重启后休息处](screenshots/ui037-process-restart-loaded.png)，实际牌组差异来自 tm_master_deck，不凭该画面猜测。

只读定位，供 Claude 修复：

- `mod/TowerMaster/RunLifecycle.cs:24` 给 SetUpSaved* 挂普通 postfix；`:33` AfterSavedRun；`:37` 先看 LocalIsMaster，不是塔主则直接返回；`:39` 才安排 Publish。
- `mod/TowerMaster/Test3MasterAutoPilot.cs:147` LocalIsMaster 从当前 RunManager.NetService.Type 判断 Host。
- **`decompiled/sts2/MegaCrit.Sts2.Core.Runs/RunManager.cs:285`**：原版 `Task SetUpSavedMultiplayer(RunState state, LoadRunLobby lobby)` 是 async；`:293` 先 await IncrementNumReloads；`:294` 才 InitializeShared 设置联机服务；`:300` 初始化大厅；后续才完成读档初始化。
- `RunManager.cs:347` 设置 NetService。普通 Harmony postfix 对 async 返回 Task 的方法，并不自动等待异步任务完成。由此存在“postfix 运行时新进程还没有 Host 服务，因此直接返回”的时序风险；同进程可能还保留旧服务状态，不能证明新进程安全。
- `MasterRewards.cs:109` 附近 Ready 调 EnsureLoaded，让休息处入口补回钱包与奖励标记，但不会自动补发牌组；因此能解释“余额/不重弹正确，而真实牌组错误”。

上述时序是源码支持的原因候选，本轮没有插入探针直接观测 postfix 当时的 NetService，不能把它写成已经动态证实。建议在真正异步读档完成且身份/动作队列就绪后恢复并同步牌组，再做完整进程重启回归。
