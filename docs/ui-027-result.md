## 必须修复：同进程换局后重复订阅

复现顺序：启动两端 → 新局第一场，塔主阶段 B 被暂停 → B 返回主菜单 → 同进程重新建房加入、新开局 → 正常打完战斗。第一次胜利已经重复收入；第二次仍重复。之后存档返回菜单再加载，下一次 TurnStarted 的重复次数增加为三次。

第一次胜利原文：


只读代码依据：

- decompiled/sts2/MegaCrit.Sts2.Core.Combat/CombatManager.cs:59，`static CombatManager Instance` 是一次创建的单例，同进程换局不会自动换对象。
- mod/TowerMaster/SummonPhase.cs:96 的 ResetRun 在:107清空 `_subscribedManager`；AfterSetUp(:315)随后重新检测/订阅，:335 AddEventHandler(CombatWon)。未找到对应 RemoveEventHandler。
- mod/TowerMaster/ThreatPhase.cs:112 的 ResetRun 在:123清空 `_subscribed`；AfterSetUp(:131)重新订阅；Subscribe(:166–170)登记 TurnStarted、CombatEnded、CombatWon，Hook(:178) AddEventHandler。未找到对应 RemoveEventHandler。

据此，重置订阅标记但未解绑原单例上的委托，导致下次战斗再次加订阅，与实测重复次数随换局/读档增加高度吻合。请开发者修复生命周期订阅并回归；本轮未修改代码。
