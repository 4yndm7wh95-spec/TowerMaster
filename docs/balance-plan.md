# 平衡测试与调整方案

目标（设计文档）：**整局胜率 爬塔玩家 40% / 塔主 60%**；玩家输了要觉得「被算计了」而不是「被数值碾压」；塔主每个房间都有事做、有决定可做。
胜率不能纸上算出来，只能「先测清楚数值，再一次只动一类旋钮」地迭代。下面分四部分：要知道哪些数、怎么得到、怎么调、Codex 怎么测。

## 1. 我想了解的数值（指标）

| 层级 | 指标 | 为什么要看 | 目标 / 警戒线（第一版，测后再修） |
|---|---|---|---|
| 单场 | **玩家掉血**（相对原版同幕同房间） | 塔主让一场战斗难了多少 | 普通战 +20%～+50%；精英 +10%～+40%；Boss +0%～+30% |
| 单场 | 回合数 | 战斗是否被拖得太长 | 不超过原版 1.5 倍 |
| 单场 | 击倒次数（多人） | 是否出现秒杀 | 每幕 ≤ 1 次为宜 |
| 单场 | 塔主花费 / 标准开销 | 塔主是在原版强度附近还是长期顶上限 | 平均 1.0～1.4 |
| 经济 | 每场前后的召唤点、作废 | 塔主是钱总不够还是总用不完 | 作废 < 10%；连续 2 场以上为 0 点的情况少见 |
| 经济 | 选「按原版出场」的比例 | 面板是否好用、钱是否够 | < 30% |
| 塔主回合 | 每场威胁点用掉多少、各操作次数 | 点数是否太少（「挂两个 buff 就没事干」）或太多 | 用掉率 > 80%；每场至少 2 个回合有操作 |
| 陷阱 | 盖下 / 触发 / 躲过 | 陷阱是否有存在感、躲过奖励是否太肥 | 触发率 40%～60% |
| 整局 | 结束楼层、胜负 | 最终胜率 | 40 / 60 |

所有单场数据由 mod 自动记录（**平衡记录**，见第 2 节），整局结果由测试报告记录。

## 2. 怎么得到这些数（调研方法）

1. **平衡记录**（0.0.25 新增）：塔主那台电脑每打完一场，往 `日志文件名.balance.jsonl`（默认 mods/TowerMaster/towermaster.balance.jsonl）追加一行：
   房间、幕、楼层、开局保护、召唤方式（自选/原版）、阵容、实际生成的怪和总血量、标准开销、怪物花费、陷阱花费、召唤前后余额、
   盖下/触发/躲过的陷阱、威胁点（分配、用掉、每种操作次数）、回合数、胜负、每名玩家开场/结束血量和最大血量、掉血、击倒、收入、作废、战后余额。
   测试接口 `tm_balance` 按「幕-房间」汇总，`tm_logs source=balance` 取原始行。
2. **基准机器人**（0.0.25 新增 `tm_autoplay`）：爬塔玩家按固定策略出牌（attack：先攻击；block：先技能），塔主按固定策略花威胁点（none / greedy / debuff）。
   机器人打得不聪明，但**每次打法一样**，所以「同样的机器人、不同的塔主设置」之间的差别就是塔主设置造成的。绝对胜率要靠真人测，相对强弱靠机器人。
3. **原版基准**：塔主全程「按原版出场」、不挑陷阱、威胁点设 0（配置 `threat_per_battle: [0,0,0]`、`threat_elite_bonus: 0`、`threat_boss_bonus: 0`），用同样的机器人打，得到原版各幕各房间的掉血、回合数。之后所有数据都和它比。
4. **离线经济模拟**：`python scripts/balance_sim.py --policy standard|cap|save [--climbers N] [--config 文件]`，不开游戏，用价格表和配置算一局三幕的召唤点曲线。
   当前默认值的结果：照标准开销花，每幕结余 +13～+10（幕末 25/34/44）；每场都顶上限花，钱只够撑约 6 场，之后被收入卡住（每幕末 6～8）。
   结论：**塔主大约能在一半到六成的战斗里打满上限**，经济大体合理，真正要测的是「顶上限时一场到底多难」。
5. **真人试玩**：机器人测不出「爽不爽」「憋不憋屈」。每轮至少 1～2 场真人对局，记录主观感受（原话）。

## 3. 怎么调（调整方案）

**规则：一次只动一类旋钮；每个设置至少 10 场同类战斗；先单场、再经济、最后整局胜率。** 数值都在 `towermaster.config.json`，不用改代码。

| 症状（看哪个指标） | 先动的旋钮 | 每步幅度 |
|---|---|---|
| 塔主顶上限时普通战掉血 > 原版 1.6 倍 | `normal_spend_cap_multiplier` ↓ | 0.1 |
| 顶上限也只比原版难一点（< 1.2 倍） | `normal_spend_cap_multiplier` ↑ 或 `cross_act_hp_cut` ↓ | 0.1 / 0.05 |
| 跨幕怪太强 / 没人用 | `cross_act_hp_cut`、`cross_act_price_premium` | 0.05 / 0.25 |
| 精英房太狠 / 太弱 | `elite_spend_cap_multiplier`、`elite_room_discount` | 0.1 / 0.05 |
| 塔主钱总不够（多场 0 点、原版出场多） | `base_income` 每幕 +1 | 1 |
| 塔主钱用不完（作废多、幕末接近上限） | `base_income` −1 或 `savings_cap` ↓ | 1 / 5 |
| 威胁点太少，「没事干」 | `threat_per_battle` +1 | 1 |
| 塔主回合太强（力量叠满秒人） | `threat.strength_cap_per_act` ↓、`threat.strength_cost` ↑ | 1 |
| 陷阱几乎都不触发 / 躲过金币太肥 | `dodge_reward_gold` ↓，或改陷阱触发门槛（代码） | 5 |
| 陷阱太容易触发、太痛 | 陷阱数值（`Traps.cs`）或 `max_traps_per_battle` ↓ | — |
| 开局几场太难 / 太简单 | `opening_protection_battles`、`opening_spend_cap_multiplier` | 1 / 0.1 |
| 多人时太难 / 太简单 | `climber_income_factor` | 0.1 |
| 整局胜率偏离 40/60 | 先 `base_income`（大步），再 `threat_per_battle`（小步） | 1 / 1 |

调完后写进 `docs/balance-results.md`：日期、配置改动、样本数、关键指标变化、结论。确认有效的改动再由我改进代码默认值。

## 4. Codex 实地测试步骤

前提：0.0.25 已安装；`towermaster.test.json` 里 `master_turn=true`；**禁用换皮 mod**（用户要求，保证原版英雄画面）；新开局。全部由测试助手操作，不需要用户手动。

**第 0 轮：原版基准（约 20 场）**
- 配置：`threat_per_battle: [0,0,0]`、`threat_elite_bonus: 0`、`threat_boss_bonus: 0`（关掉塔主回合）。
- 每场 `tm_battle`：`vanilla=true`、`autoplay=true`、`policy=attack`、`master_policy=none`；每幕第一次挑陷阱时 `draft=[]`（不挑）。
- 打到第二幕中段或玩家倒下为止；记录 `tm_balance` 汇总。再用 `policy=block` 打一局对照。

**第 1 轮：召唤强度（每个条件 ≥ 10 场普通战）**
- 配置恢复默认。威胁点仍设 0、不盖陷阱，只看召唤。
- 条件 A：每场选「标准开销附近」的阵容（花费 ≈ 标准）。条件 B：每场顶到上限（花费 ≈ 上限）。条件 C：每场用 1 只跨一幕的怪 + 便宜小怪。
- 阵容从 `tm_summon` 的列表里按条件挑（写清挑选规则，固定下来）。机器人 `policy=attack`。
- 对比第 0 轮：掉血、回合数。

**第 2 轮：塔主回合（≥ 10 场）**
- 召唤用条件 A；威胁点默认；`master_policy=greedy` 和 `debuff` 各 5 场以上。看威胁点用掉率、每回合是否有事做、掉血增加多少。

**第 3 轮：陷阱（≥ 10 场）**
- 召唤用条件 A，威胁点 none；每幕挑满陷阱，每场盖 2 张（轮换，注意冷却）。看触发率、躲过金币总额、触发时掉血增量。

**第 4 轮：整局（至少 3 局，能多则多）**
- 默认配置，塔主按「条件 A/B 交替 + greedy + 每场盖 1～2 张陷阱」；机器人 `policy=attack`。记录每局结束楼层、胜负、召唤点曲线（`tm_balance` 的 points_curve）。
- 另请用户真人打 1 局（爬塔玩家或塔主任一方），记录原话感受。

**每轮交付**：`docs/balance-results.md` 追加一节（配置、条件、样本数、`tm_balance` 汇总表、和基准的对比、异常）；原始平衡记录不用提交全文，摘要即可。
根据结果提出 1～3 条调整建议（按第 3 节的表），下一轮再验证。

## 5. 已知限制

- 机器人不看怪物意图、不用药水，绝对难度偏高；只用来做相对比较。
- 平衡记录只在塔主那台电脑写；「?」房间里的战斗没有召唤记录（summon=none）。
- 1 名爬塔玩家时测不到击倒奖励和多人系数。
