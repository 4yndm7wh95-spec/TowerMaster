# 塔主的真实卡牌系统（设计方案，待接口调研后实现）

用户要求（`docs/balance-review-request.md` 末尾）：
> 我要的是把塔主那个角色的卡牌就换成这些牌，套进原版的框架，让这些卡牌可以在牌组中看见，而不是模仿原版的样式然后又做一个面板展示这些卡牌。

现在（0.0.26）的做法是借原版卡牌的**外观**（实例化 card.tscn）放在自建面板里，**不算**完成。要做的是：塔主的牌是游戏里真正的卡牌（CardModel），在原版牌组界面里能看到，战斗中用原版手牌、能量、拖拽到目标的方式打出。

## 1. 怎么把新卡放进游戏

- 已有先例：mod 已经在运行时用 Reflection.Emit 生成了 `GameAction` 的子类（`RuntimeNetAction`），并登记到 mod 名下。卡牌用同样办法：运行时生成 `CardModel` 子类，构造里传（费用、类型、稀有度、目标类型），重写 `OnPlay` 转到我们自己的静态方法。
- 游戏有 `ModelDb.Inject(Type)` 和 `ModelDb.Init(Type[] injectedModelTypes)`，看起来就是给新内容用的。具体时机、编号、卡池、本地化、卡图要调研（第 4 节）。
- 不注册新角色：塔主仍然是原来那名玩家（房主），只是**牌组换成塔主牌**。

## 2. 规则（我定的暂定方案，用户可以改）

| 项 | 方案 | 理由 |
|---|---|---|
| 塔主牌组 | 开局把塔主的英雄牌换成 8 张：加固×2、激励、治疗、虚弱、易伤、脆弱、晕眩 | 和现在的行动卡一一对应，规则已测过 |
| 在哪看 | 原版牌组按钮（顶栏）看到的就是这些牌 | 用户要求 |
| 战斗中 | 原版手牌：每回合抽 4 张，原版能量当「威胁点」，费用沿用现在的价格（加固/治疗/减益/晕眩 1，激励 2，战吼 3） | 抽牌让每回合的选择不同，有构筑感；不需要单独的威胁点面板 |
| 能量 | 每回合 1 / 1 / 2（按幕），第 1 回合 +1（先手），精英、Boss 每回合 +1 | 和 0.0.26 的总量大致相同：第一幕普通战 3 回合 = 2+1+1 = 4（现在 3） |
| 出牌时机 | 保留「塔主先手」：玩家回合开始时爬塔玩家的队列暂停，塔主出完牌按原版「结束回合」后恢复 | 玩家能看到塔主做了什么再出牌；需要调研能不能只暂停爬塔玩家的队列 |
| 目标 | 给怪的牌（加固、治疗、激励）= 原版「选一名敌人」的拖拽目标；给玩家的牌（减益、晕眩）=「选一名队友」 | 原版操作，不用自建目标按钮 |
| 限制 | 每回合每名玩家最多被上 1 次减益、每只怪治疗 2 次、力量上限 2/3/4：卡牌不满足时不能打出（原版的「不能打出」提示） | 各端都执行同一张牌，判断要在各端一致 |
| 陷阱牌 | 也是真卡，在牌组里能看到，类型字写「陷阱」；战斗中不进抽牌堆，召唤时从牌组里挑来盖 | 用户要能在牌组看到；盖牌仍在召唤面板里做 |
| 挑陷阱 | 每幕开头的自由挑选保留（预算、张数、不重复、冷却），选中的加进牌组 | 用户认可的规则不变 |
| 以后 | 精英/Boss 战后塔主像玩家一样 3 选 1 拿新的塔主牌（升级版、新效果） | 构筑成长，后续再做 |

保留的面板：召唤面板（选怪、筛选）、左上角玩家信息（塔主要看玩家手牌）。去掉：底部自建行动卡条、头顶目标按钮、威胁点数字。

## 3. 风险

- 注入的卡如果混进普通卡池，会出现在玩家的卡牌奖励、商店里 → 要放进单独的卡池或确认不会被抽到。
- 存档里会存这些卡的编号：两边都装 mod 时没问题，卸载 mod 后读档可能报错。
- 原版能量、抽牌改成塔主专用的数值，要确认能只对塔主一人生效。
- 塔主的角色在战斗中隐藏着，原版手牌界面要在塔主自己的屏幕上正常显示。
- 只暂停爬塔玩家队列如果做不到，退一步：塔主和玩家同时出牌（简单但失去「先手」）。

## 4. 需要测试助手先查的接口（只读反编译源码，写出文件和行号）

1. `ModelDb.Init / Inject / InitIds`：什么时候调用？mod 能不能在游戏启动后注入？编号怎么来（类型名？）？会不会扫描 mod 程序集（像 `ReflectionHelper.ModTypes`）？有没有现成 mod 注入内容的流程（`ModManager` 里）？
2. `CardModel`：构造参数、必须重写的成员；标题和说明从哪里来（`LocString("cards", "XXX.title")`？）；运行时怎么往本地化表里加条目（`LocManager` 的接口）；数字用 `DynamicVar` 怎么写。
3. `CardModel.Pool`：卡池怎么确定；不在任何卡池里会怎样；能不能重写成无色卡池或自建卡池；`VisualCardPool` 决定卡框颜色吗；会不会被卡牌奖励、商店、随机生成抽到（`CanBeGeneratedInCombat`、`CanBeGeneratedByModifiers`、`ShouldShowInCardLibrary`）。
4. 卡图：`PortraitPath` / `Portrait` 怎么加载；能不能给一张从文件读的贴图（我们的 art/*.png）。
5. 开局牌组：玩家的初始牌组在哪里生成（`CharacterModel` 的初始牌组？`Player.Deck`？）；联机时怎样确定性地替换某一名玩家的牌组；原版牌组界面读的是哪里。
6. 单个玩家的抽牌数、能量上限：有没有 Hook（如 `ModifyHandDraw`、`ModifyMaxEnergy`）能只改塔主。
7. `TargetType` 全部取值；「选一名队友」（AnyAlly 之类）在联机里怎么选、怎么校验；玩家的牌能不能指定怪物以外的目标。
8. `ActionQueueSet`：能不能只暂停某几名玩家的队列（塔主的继续执行）？
9. 结束回合：玩家按「结束回合」走什么动作（`EndPlayerTurnAction`？`IsPlayerReadyToEndTurn`？）；能不能截住塔主的结束回合当作「塔主先手结束」，而不影响整轮结束的判断。
10. 打牌同步：`PlayCardAction` 是不是每端都执行 `OnPlay`；`CanPlay` / `IsPlayable` 在哪里判断（发起端还是各端）。
11. 不能打出的牌、战斗开始时把某些牌移出抽牌堆（给陷阱牌用）：有没有 `Unplayable` 关键词、战斗开始的 Hook。
12. 存档：卡牌按什么存（ModelId？）；读档时找不到类型会怎样。
13. 参考：本机装的其它 mod（如川换皮）有没有加新内容，怎么加的。

## 5. 进度（0.0.28）

调研结果见 `docs/master-cards-research.md`。按调研结论分两阶段：

**第一阶段（0.0.28，开关 `master_cards`，默认关，两台电脑必须一致）**
- `MasterCards`：mod 入口里（ModelDb.Init 之前）用 Reflection.Emit 生成 54 种 CardModel 子类（行动牌 8 种 × 3 幕，陷阱 10 种 × 3 级），
  挂进 `ReflectionHelper.ModTypes`，ModelDb.Init 和联机编号缓存就会收录（研究第 1 条：晚 Inject 不进编号缓存）。
- 标题重写 `Title`；标题和说明在 `LocManager.GetTable("cards")` 之后 `MergeWith` 进去（每个表实例补一次，切语言后的新表会再补）。
- 卡池借无色卡池但不加入卡池列表 → 不进 `ModelDb.AllCards`、奖励、商店；`CanBeGenerated*` = false；图鉴不显示；稀有度 Token。
- 卡图：`PortraitPath` = 原版缺图路径（保证能加载），`NCard.UpdatePortrait` 之后换成 art/*.png（每次刷新都会换）。
- 陷阱牌带「不能打出」。
- `MasterDeck`：新局（`SetUpNewMultiplayer` 之后，各端相同）把塔主牌组换成第一幕行动牌 9 张；之后每幕挑完陷阱、每场战斗结束，
  房主算出整副（本幕行动牌 + 手里陷阱），有变化就发 `deck` 指令（NonCombat），各端 `Clear` + `PopulateDeck`。读档不动。
- 行动牌的 `OnPlay` 已经写好（加固、治疗、激励、战吼、减益、晕眩），但塔主战斗中是死亡状态，还打不出来；战斗中仍用塔主回合面板。

**第二阶段（下一步）：战斗中用原版手牌出牌**
研究第 7、8、9 条说明，关键是塔主在战斗里是「死」的（生命设 0，借用原版死亡玩家：自动准备结束回合、不被怪物选为目标、全员死才判负）。
要用原版手牌出牌，需要二选一，等第二轮调研：
- A. 塔主保持「死亡」，但放开：死亡玩家也抽牌、给能量、能打出牌（改 CanPlay 等）、手牌界面显示。
- B. 塔主活着但隐藏：怪物不选他当目标、群体伤害不打他、判负只看爬塔玩家、整轮结束的准备判断、复活/血量。
然后：只暂停爬塔玩家的队列（反射私有 ActionQueue.isPaused，各端同一动作里改）、塔主的「结束回合」当作先手结束（EndPlayerTurnAction 执行层识别塔主）、
单人抽牌数/能量（`Hook.ModifyHandDraw`、`Hook.ModifyMaxEnergy` 只对塔主）、陷阱牌战斗中移出抽牌堆（`Player.PopulateCombatState` 之后过滤）、
各种次数限制改成各端一致地在 `IsPlayable` / 目标校验里判断。
