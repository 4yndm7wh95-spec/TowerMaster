# 测试 2：塔主不上场（mod 0.0.4）

## 这一版做了什么

- **塔主 = 房主**。单人模式下测试 2 完全不生效。
- **塔主角色开局退场**：每场战斗初始化（`CombatManager.SetUpCombat`）后，各客户端把塔主角色的生命直接写成 0，不走伤害流程。借用游戏现成的「死亡玩家」处理：
  - 每回合自动准备结束回合；
  - 不会被怪物选为目标；
  - 「所有玩家都死才判负」变成「爬塔玩家都死才判负」。
  - 战斗结束原版会给死亡玩家回 1 血，这一版不拦，下一场开局再写成 0。
- **人数缩放只数爬塔玩家**：在指定范围内，把「读玩家人数」（`Players.Count` / `.Length` / `.Count()`）改成只数爬塔玩家。默认范围：
  - 怪物、能力（Powers）命名空间；
  - `Creature`、`MultiplayerScalingModel`、`PowerModel` 类；
  - `CreateCreature`、`ScaleHpForMultiplayer`、`ScaleMonsterHpForMultiplayer`、`ModifyBlockMultiplicative`、`GetScaledAmountForMultiplayer` 方法。
  - 启动日志会列出**整个游戏里所有读玩家人数的方法**，★ 表示已改写。
- 测试 1b 的混搭保持开启，顺带验证混搭怪物的完整战斗。

## 预期数值（用来判断人数缩放是否生效）

1 塔主 + 1 爬塔玩家时，怪物血量应和**单人**一样：

| 幕 | 怪物 | 单人血量 |
| --- | --- | --- |
| 密林 | 蛮兽 Mawler | 72 |
| 密林 | 飞蝇菌子 Flyconid | 47–49 |
| 暗港 | 钙化邪教徒 CalcifiedCultist | 38–41 |
| 暗港 | 海洋混混 Seapunk | 44–46 |

明显更高（大约翻倍）就是缩放没改到。

## 测试步骤

1. 两个实例都装 0.0.4（`TowerMaster.json` 里 version 是 0.0.4）。A 建房（A 就是塔主），B 加入，新开一局，只打第一幕。
2. 正常打 3 场普通战斗，不用 win 命令。如果有精英房也可以打。
3. 最后一场故意让 B 死掉，看是否判负。这一步会结束对局，放在最后。
4. 正常退出两个实例，保存两边的 TowerMaster 日志和游戏日志（新启动会覆盖）。

## 要观察和记录的事项

**启动（看 TowerMaster 日志）**
- 探针段有没有 WARN。
- 「测试2：共 N 个方法读玩家人数，改写 M 个」这一行，以及有没有「改写失败」ERROR。

**每场开局（看 TowerMaster 日志）**
- 「测试2 开局 玩家 …（塔主）：生命=0/… 死亡=True」；B 的生命正常、死亡=False。
- 「测试2 开局 爬塔人数=1」。
- 「测试2 开局 怪物 …：生命=…」：对照上表，血量是否等于单人。
- 「测试2 参数 …」：缩放公式收到的人数是 1 还是 2。
- 两边这些行是否一致。

**战斗中（看画面）**
- A 的角色是什么样子（倒地、消失、还站着）。A 能不能出牌，界面有没有异常。
- B 结束回合后，是否不用等 A 就进入怪物回合。
- 怪物是否只打 B。有没有怪物出招却打空、没造成伤害。
- 两边的怪物意图、血量、伤害数字是否一致。

**战斗结束（看画面）**
- B 打赢后，A 是否被复活成 1 血，A 有没有奖励界面。
- 选路、领奖励时是否卡在「等待其他玩家」。这是测试 3 的内容，先记录现象即可。

**判负**
- B 死亡后，两边是否都进入失败结算。还是继续战斗、卡住、报错。

**异常（两边都看游戏日志）**
- `StateDivergence`。
- A 这边有没有因为本地玩家死亡而报错，比如 `GetMe`、NullReference、InvalidOperation。
- 测试 1b 的「拒收召唤清单」「替换遭遇失败」等 ERROR/WARN。

## 要回传的东西

- 两边的 TowerMaster 日志、游戏日志。
- 每一项观察的结果，特别是：怪物血量、A 的样子、回合是否等 A、怪物是否打空、复活和奖励、判负。
- 战斗中 A 角色状态的截图。
